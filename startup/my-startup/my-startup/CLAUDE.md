# CLAUDE.md — 한 줄 회고 보드 회사 규칙

기준 문서는 `PRD.md`예요. 이 파일은 "꼭 필요한 규칙"만 담았어요. (있으면 좋은 규칙은 사용자가 고르면 추가)

## 기록 보호
1. `data/entries.csv`는 지우거나 통째로 덮어쓰지 않아요. 새 기록은 맨 아래에 덧붙이기만 해요. (파일을 새로 쓰다 기록이 날아가는 사고를 막아요)
2. 기록 삭제 기능과 삭제 버튼은 만들지 않아요. (PRD에서 이번 버전에 하지 않기로 했고, 실수로 누르는 일이 없어져요)
3. `python make_sample.py --reset`은 사용자가 직접 허락했을 때만 실행해요. (기존 기록을 지우고 가짜 기록으로 바꾸는 명령이라서요)

## 검사하기 쉬운 구조
4. 계산(연속 일수, 주간 요약, 글자 수 세기)은 화면 코드와 따로 둬요. (테스트 직원이 화면 없이 계산만 바로 검사할 수 있어요)
5. 계산 함수는 "오늘 날짜"를 직접 읽지 않고 받아서 써요. (날짜를 정해 놓고 검사할 수 있어서 결과가 날마다 달라지지 않아요)
6. 새 기능을 만들 때마다 pytest 검사 코드를 같이 만들어요. 검사는 진짜 `data/entries.csv`가 아니라 임시 파일로만 해요. (고치다 예전 기능이 망가져도 바로 알 수 있어요)

## 빈 상태에서도 멀쩡하게
7. `entries.csv`가 없거나, 제목 줄만 있거나, 기록이 0개여도 오류 없이 열려요. (처음 열었을 때 "첫 한 줄을 남겨 보세요"가 보여야 해요)
8. `mood`가 비어 있는 예전 기록도 깨지지 않게 다뤄요. (빈칸 때문에 화면이 멈추는 일이 없어요)

## 숫자는 정확하게
9. 화면의 숫자는 PRD 4장 완료 기준대로 계산해요. 어림짐작이나 반올림은 하지 않아요. (하루만 틀려도 앱을 믿을 수 없게 돼요)
10. 같은 날 여러 줄은 하루로 세고, 한 주는 월~일로 계산해요. (숫자 오류가 가장 자주 나는 곳이에요)
11. 글자 수는 앞뒤 공백을 뺀 뒤 화면에 보이는 글자 기준으로 세요. (100자 제한이 사람마다 다르게 느껴지지 않아요)

## 에러는 한국어로
12. 에러 메시지는 쉬운 한국어로, "무엇이 문제인지"와 "어떻게 하면 되는지"를 같이 적어요. 영어 에러 원문은 화면에 그대로 보여 주지 않아요. (코드를 모르는 사용자가 바로 다음 행동을 정할 수 있어요)

## 깃허브
13. `git commit`, `git push`, PR 만들기는 사용자가 "올려줘"라고 말했을 때만 해요. (다듬는 중인 내용이 공개되는 걸 막아요)

## 프로젝트 기본 약속
14. PRD에 없는 기능(로그인, 공유, 광고·결제 등)은 만들지 않아요. 기능은 사용자가 말한 범위까지만 만들어요. (AI가 알아서 기능을 늘려 앱이 복잡해지는 걸 막아요)
