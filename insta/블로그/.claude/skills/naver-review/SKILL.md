# naver-review

네이버 블로그 후기 글을 대신 쓰는 순서. 세부 규칙은 이 폴더의 `CLAUDE.md`가 기준이고, 아래는 실제로 돌려 본 작업 순서다.

## 순서

1. **사진 확인 (있을 때만)**
   첨부 사진은 분석용으로만 쓴다. 메뉴 이름, 분위기, 답에 없는 메뉴를 파악한다.
   결과 HTML에는 사진을 넣지 않는다 (`<img>`, base64, 외부 주소 X).

2. **reference 읽기**
   `예시글_맛집.html`, `예시글_카페.html`, `예시글_여행.html` 3개를 처음부터 끝까지 읽고
   형식·문체를 추출한다. (`reference` 폴더가 생기면 거기서 읽는다.)

3. **질문 10개를 한 메시지로 묶어서 묻기**
   이미 답한 항목은 빼고 모르는 것만 묻는다.
   1 시킨 메뉴 전체 / 2 메뉴별 가격 / 3 베스트 메뉴와 한 줄 평 / 4 동행 / 5 분위기 한 단어 /
   6 별점과 재방문 / 7 방문 동기 / 8 시간대와 웨이팅 / 9 특이사항 / 10 결제 금액
   - 사용자가 리뷰나 메모를 붙여넣으면 거기서 읽을 수 있는 항목부터 채우고 나머지만 다시 묻는다.
   - 사용자가 "안 알려줘도 돼"라고 한 항목(예: 결제 금액)은 글에서 뺀다.

4. **가게 정보 검색**
   주소, 영업시간, 라스트오더, 브레이크타임, 전화, 주차를 찾는다.
   - 네이버 도메인(blog, map, place)은 WebFetch와 내장 브라우저가 막혀 있다. 못 읽으면 지어내지 말고,
     사용자에게 네이버 지도 가게 정보를 붙여넣어 달라고 요청한다.
   - 못 찾은 값은 `[확인 필요]`로 둔다. 체인점은 다른 지점 이름을 나열하지 않는다.

5. **HTML 만들기**
   reference의 `<style>`을 그대로 복사하고, 섹션 순서, 정보 블록(📍⏰🚗), 메뉴 카드, 별점 줄,
   해시태그 5개, "~요" 체와 마침표 없는 문장까지 그대로 따른다. 새 클래스, 태그, 이모지는 만들지 않는다.
   - 메뉴 카드는 사용자가 시켰다고 한 메뉴만. 가격을 모르면 `[가격 확인 필요]`.
   - 사진 자리는 `[사진: 구체적인 설명]` 한 줄. 사용자가 찍지 않았다고 한 사진은 자리를 만들지 않는다.
   - "강추", "인생 맛집", "미쳤다" 같은 과장은 담백하게 바꾼다. 사용자가 안 먹어 본 메뉴는 맛을 평가하지 않는다.
   - 출처·면책 문구, 다른 사람의 리뷰 내용은 쓰지 않는다.
   - 서비스·이벤트는 해당 메뉴 섹션에서 한 번만 언급한다.

6. **저장**
   `글/날짜_가게이름.html` (예: `글/2026-11-06_라라스시.html`). 날짜는 `YYYY-MM-DD`.

7. **수정**
   수정 요청이 오면 새 파일을 만들지 않고 같은 파일을 고친다.
   채팅 답은 짧게: 만들었다는 말, 파일 경로, 아직 비어 있는 `[확인 필요]` 목록.

## 하지 않는 것
- 블로그 게시, 발송, 로그인은 하지 않는다. 초안 파일까지만 만든다.
- 파일 삭제 전에는 반드시 먼저 묻는다.
