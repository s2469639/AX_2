# 코드 작성 규칙

## 작업 방식

- 한 번에 파일 하나씩 작성하거나 수정한다.
- 파일을 수정한 뒤 변경 내용을 **3줄**로 요약해 사용자에게 알린다.
- 사용자 승인 없이 기획서에 없는 기능을 추가하지 않는다.
- 문서 설계 단계(1단계)에서는 코드를 작성하지 않는다.

## 코드 스타일

- Python 3.11+ 기준, `.venv` 가상환경에서 실행한다.
- 모든 함수에 **한국어 주석을 한 줄 이상** 작성한다 (함수 역할 설명).
- 함수는 한 가지 일만 하도록 짧게 나눈다.
- 설정값(모델명, 검색 개수, 예산 한도 등)은 한 곳에 모아 관리한다.

## 라이브러리

- 기획서의 기술 스택(Streamlit, LangChain, LangGraph, Chroma, OpenAI) 외의 라이브러리는 추가하지 않는다. 꼭 필요하면 이유를 설명하고 승인을 받는다.
- import 경로는 **설치된 버전 기준**으로 확인한 뒤 사용하고, 결과를 `조사노트.md`에 기록한다.
- 사용 중단(deprecated) 경고가 나오면 무시하지 말고 원인을 확인해 기록한다.

## 오류 메시지

- 비전공자도 이해할 수 있는 쉬운 한국어로 작성한다.
- "무엇이 문제인지 + 어떻게 하면 되는지"를 함께 알려준다.
  - 좋은 예: "문서 검색 준비가 아직 안 됐어요. 먼저 `python ingest.py`를 실행해 주세요."
  - 나쁜 예: "CollectionNotFoundError"
- 기술적인 원본 오류는 화면 대신 터미널 로그에만 남긴다 (키 정보 제외).

## 답변 생성 규칙

- 검색된 문서에 있는 식당·선물만 추천한다. 문서에 없는 항목을 만들어내지 않는다.
- 추천 결과에는 추천 이유, 주의사항, 출처를 반드시 포함한다.
- 국가별 고정관념으로 판단하지 않고, 최신 확인이 필요한 정보는 단정하지 않는다.

## 테스트

- 기능을 추가하면 기획서 6단계 테스트 항목 중 관련 항목으로 동작을 확인한다.
- 확인 결과(성공/실패, 원인)는 `조사노트.md`에 기록한다.
