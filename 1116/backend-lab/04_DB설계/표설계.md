# 표 설계 — (가상) 무역 문의를 3개 표로 나누기

> 출발점: `무역문의_엑셀한장_가상.csv` (문의 5건이 한 장에 다 들어 있음)
> 원칙: **한 가지 정보는 한 곳에만** 적고, 다른 표에서는 **번호로 가리킨다.**
> 칸 이름은 다음 섹션 `05_Supabase/01_테이블만들기.sql` 과 맞춰 두었어요. (아직 SQL 은 만들지 않음)

---

## 한눈에 보기 — 어떤 칸이 어느 표를 가리키나 (외래 키)

```
┌──────────────────────┐                    ┌──────────────────────┐
│       buyers         │                    │      products        │
│      (바이어)         │                    │       (상품)          │
├──────────────────────┤                    ├──────────────────────┤
│ 🔑 id                 │◄──────┐    ┌──────►│ 🔑 id                 │
│    company           │       │    │       │    name              │
│    country           │       │    │       │    unit_price_usd    │
│    email             │       │    │       │    stock             │
│    created_at        │       │    │       └──────────────────────┘
└──────────────────────┘       │    │
                               │    │
                  ┌────────────┴────┴────────┐
                  │        inquiries         │
                  │         (문의)            │
                  ├──────────────────────────┤
                  │ 🔑 id                     │
                  │ 🔗 buyer_id   ──► buyers.id   │
                  │ 🔗 product_id ──► products.id │
                  │    quantity              │
                  │    quoted_unit_price_usd │
                  │    status                │
                  │    created_at            │
                  └──────────────────────────┘

🔑 = 기본 키 (그 표 안에서 한 줄을 콕 집는 번호)
🔗 = 외래 키 (다른 표의 줄을 가리키는 번호)
```

- **바이어 1명 ──< 문의 여러 건** : Sunrise Trading 한 회사가 문의를 3번 할 수 있어요.
- **상품 1개 ──< 문의 여러 건** : 샘플 상품 A 하나에 문의가 3번 들어올 수 있어요.
- 문의 한 건은 **꼭 바이어 1명 + 상품 1개**를 가리켜요.

---

## 1. buyers — 바이어 (회사 1곳 = 1줄)

| 칸 이름 | 뜻 | 타입 | 필수 | 중복 금지 | 비고 |
|---|---|---|:---:|:---:|---|
| `id` | 바이어 번호 | 정수 (자동 증가) | ✅ | ✅ | 🔑 기본 키. 직접 쓰지 않고 자동으로 붙어요 |
| `company` | 회사명 | 글자 | ✅ | — | 이름이 같은 다른 회사가 있을 수 있어 중복 허용 |
| `country` | 국가 | 글자 | ✅ | — | |
| `email` | 담당자 이메일 | 글자 | ✅ | ✅ | 같은 바이어인지 알아보는 기준 (설계서 ③ "같은 이메일이면 그 바이어로 연결") |
| `created_at` | 처음 등록된 시각 | 날짜+시간 | 자동 | — | 비워 두면 지금 시각이 들어가요 |

## 2. products — 상품 (상품 1개 = 1줄)

| 칸 이름 | 뜻 | 타입 | 필수 | 중복 금지 | 비고 |
|---|---|---|:---:|:---:|---|
| `id` | 상품 번호 | 정수 (자동 증가) | ✅ | ✅ | 🔑 기본 키 |
| `name` | 상품명 | 글자 | ✅ | ✅ | 같은 이름의 상품이 두 개면 헷갈리니 금지 |
| `unit_price_usd` | **기본(정가) 단가** (USD) | 소수 가능한 숫자 | ✅ | — | 0보다 커야 해요 |
| `stock` | 재고 | 정수 | ✅ (기본 0) | — | 0 이상. CSV 에는 없지만 05_Supabase 예시에 있어서 맞춰 둠 |

## 3. inquiries — 문의 (문의 1건 = 1줄)

| 칸 이름 | 뜻 | 타입 | 필수 | 중복 금지 | 비고 |
|---|---|---|:---:|:---:|---|
| `id` | 문의 번호 | 정수 (자동 증가) | ✅ | ✅ | 🔑 기본 키 (CSV 의 "문의번호") |
| `buyer_id` | 어느 바이어? | 정수 | ✅ | — | 🔗 **→ buyers.id**. 없는 바이어 번호는 못 넣어요 |
| `product_id` | 어느 상품? | 정수 | ✅ | — | 🔗 **→ products.id**. 없는 상품 번호는 못 넣어요 |
| `quantity` | 수량 | 정수 | ✅ | — | 1 이상 |
| `quoted_unit_price_usd` | **이 문의에 부른 단가** (USD) | 소수 가능한 숫자 | — | — | ⭐ 꼭 필요 (4번 문의의 13 같은 "일부러 부른 가격"을 담는 곳). 비어 있으면 상품 기본 단가를 쓴다는 뜻 |
| `status` | 상태 | 글자 (정해진 값만) | ✅ (기본 "신규") | — | `신규` · `견적발송` · `계약` · `보류` 중 하나만 |
| `created_at` | 접수 시각 | 날짜+시간 | 자동 | — | CSV 의 "접수일" |

> **왜 바이어·상품 정보를 문의 표에 안 적나요?**
> 문의 표에는 **번호만** 적어요. 회사명·이메일·상품명·정가가 필요하면 번호를 따라가서 읽어 와요.
> 그래서 이메일이 바뀌어도 **buyers 표 1줄만** 고치면 모든 문의에 저절로 반영돼요.

|---|---|---|---|

**products (3줄)** — 상품마다 정가 하나

**inquiries (5줄)** — 번호로만 가리킴

| id | buyer_id | product_id | quantity | quoted_unit_price_usd | status | created_at |

## 결정이 필요한 것 — 상품 A 단가 12 / 13

CSV 의 4번 문의만 상품 A 단가가 **13**이에요. 표를 나누면 "정가"는 products 에 **한 번만** 적으니, 13을 어디에 둘지 정해야 해요.

| 4번의 13이 사실은… | 처리 |
|---|---|
| 잘못 친 값 | products 정가 12 그대로, 4번 `quoted_unit_price_usd` 는 비워 둠 |
| 이 바이어에게만 일부러 부른 가격 | 위 표처럼 4번 `quoted_unit_price_usd = 13` 으로 남김 (정가 12 는 그대로) |
| 11/6 부터 가격이 오른 것 | products 정가를 13 으로 바꾸고, 그 전 문의(1·3번)엔 `quoted_unit_price_usd = 12` 를 남김 |

→ **결정: 두 번째(일부러 부른 가격)** ✅ — 확인 완료.
products 의 상품 A 정가는 **12** 그대로 두고, 4번 문의에만 `quoted_unit_price_usd = 13` 을 남겨요.
그래서 `quoted_unit_price_usd` 칸은 **꼭 필요한 칸**이 됐어요. (SQL 만들 때 추가해야 함)

`quoted_unit_price_usd` 칸은 `05_Supabase/01_테이블만들기.sql` 예시에는 **없는 칸**이에요.
이 칸을 넣지 않으면 "정가"와 "이번에 부른 가격"을 구분할 방법이 없어서, 12/13 문제가 다시 생겨요.
위 결정에 따라 SQL 을 만들 때 inquiries 표에 이 칸을 **추가**해요.

## 나눈 뒤 좋아지는 점 (CSV 의 문제와 짝)

| CSV 의 문제 | 3개 표로 나눈 뒤 |
|---|---|
| Sunrise 정보가 3번 반복 | buyers 에 1번만 |
| 이메일 바뀌면 3줄 수정 | buyers 1줄만 수정 |
| 상품 A 단가가 12 / 13 섞임 | 정가는 products 1곳, 문의별 가격은 따로 |
| 5번 문의를 지우면 상품 C 정보도 사라짐 | 상품 C 는 products 에 그대로 남음 |
| 문의가 없으면 새 상품·바이어를 적을 곳이 없음 | products · buyers 에 먼저 등록 가능 |
| 상태를 "견적 발송"처럼 제각각 쓸 수 있음 | 정해진 4개 값만 허용 |
