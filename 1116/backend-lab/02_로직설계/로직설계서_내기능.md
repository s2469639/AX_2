# 기능 로직 설계서 — (가상) 견적 요청 접수

| 칸 | 내 답 |
|---|---|
| 기능 이름 | 견적 요청 접수 |
| 누가 쓰나 (권한) | 아무나 (홈페이지 방문자) — 요청을 내기만 가능, 다른 사람의 요청은 못 봄 |
| ① 입력 (무엇을 받나) | 회사명(필수) · 담당자 이메일(필수, 이메일 형식) · 국가(필수, 목록에서 선택) · 상품(필수, 목록에서 선택) · 수량(필수, 1 이상 정수) · 희망 납기(선택, 오늘 이후 날짜) · 무역 조건(선택, FOB / CIF / EXW 중 하나) · 요청사항(선택, 1000자 이하) |
| ② 검사 (받은 걸 확인) | 필수 칸(회사명·이메일·국가·상품·수량) 비었나 · 이메일 형식 맞나 · 수량이 1 이상 정수인가 · 국가·상품·무역 조건이 목록에 있나 · 희망 납기가 오늘 이후인가 · 요청사항이 1000자 이하인가 |
| ③ 처리 (계산 · 판단) | 같은 이메일의 바이어가 있으면 그 바이어로 연결, 없으면 새 바이어 만들기 · 상태 = "신규" · 접수 번호 만들기 |
| ④ 저장 (어느 표에 무엇을) | buyers 표: 회사명 · 이메일 · 국가 (없을 때만 새로) · quote_requests 표: 상품 · 수량 · 희망 납기 · 무역 조건 · 요청사항 · 상태 · 접수 번호 (항상) |
| ⑤ 응답 (화면에 무엇을 돌려주나) | "견적 요청이 접수되었어요. 영업일 기준 1~2일 안에 이메일로 견적을 보내 드릴게요." + 접수 번호 |
| ⑥ 예외 (잘못되면) | 필수 칸 빔 → "○○을 입력해 주세요" · 이메일 형식 틀림 → "이메일 주소를 확인해 주세요" · 수량 0 이하·소수 → "수량은 1개 이상" · 납기가 지난 날짜 → "오늘 이후 날짜를 골라 주세요" · 목록에 없는 값 → "목록에서 골라 주세요" · 요청사항 초과 → "요청사항은 1000자 이하로 써 주세요" · 서버 문제 → "잠시 후 다시 시도해 주세요" (자세한 에러 내용은 화면에 보여 주지 않기) |
| 기록 (나중에 확인용) | 접수 시각 · 접수 번호 |
